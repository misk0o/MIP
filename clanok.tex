\title{TimeManager: Inteligentný plánovač času pre študentov s integráciou Google služieb}

\begin{abstract}
Tento článok prezentuje komplexný návrh a plán realizácie webovej aplikácie TimeManager (TIMA), ktorá kombinuje princípy efektívneho time managementu s modernými technológiami a integráciou Google služieb. Aplikácia je určená primárne študentom a využíva umelú inteligenciu (Google Gemini) na inteligentné plánovanie úloh. Systém je postavený na Next.js frontende s Django backend-om a PostgreSQL databázou. Projekt je navrhnutý ako trojročný aplikovaný výskum (2026--2028) s celkovým rozpočtom 281\,600~EUR, zahŕňajúci vývoj, pilotnú prevádzku a evaluáciu dopadu na produktivitu študentov.
\end{abstract}

\section{Úvod a motivácia}

Moderný študent čelí náročnej úlohe balansovať medzi akademickými povinnosťami, osobným rastom a voľnočasovými aktivitami. Podľa prieskumu \cite{time-management-students} až 68\% vysokoškolských študentov uvádza problémy s efektívnym plánovaním času, čo vedie k zvýšenému stresu a nižšej produktivite.

Existujúce riešenia ako Todoist, Microsoft To Do či Google Tasks ponúkajú základnú funkcionalitu správy úloh, no často im chýba inteligentná prioritizácia a integrácia s akademickým prostredím. TimeManager sa snaží preklenúť túto medzeru kombináciou osvedčených metód time managementu s modernou AI technológiou.

Projekt TIMA je koncipovaný ako aplikovaný výskum na úrovni TRL 5--6, čo znamená validáciu funkčného prototypu v relevantnom prostredí s cieľom demonštrovať realizovateľnosť a merateľný dopad na cieľovú skupinu.

\section{Súčasný stav riešenia}

\subsection{Metódy time managementu}

V oblasti time managementu existuje niekoľko osvedčených prístupov. \textbf{Eisenhowerova matica} kategorizuje úlohy podľa dôležitosti a naliehavosti do štyroch kvadrantov, čo umožňuje efektívnu prioritizáciu \cite{eisenhower}. \textbf{Pomodoro technika} využíva 25-minútové intervaly práce s krátkymi prestávkami na udržanie koncentrácie \cite{pomodoro}.

\subsection{Existujúce aplikácie}

Súčasný trh ponúka množstvo plánovacích aplikácií. Google Calendar poskytuje vynikajúcu správu udalostí, no chýba mu podpora pre projektové úlohy. Notion ponúka komplexný workspace, ale je príliš zložitý pre jednoduchý time management. Todoist exceluje v správe úloh, no nemá natívnu integráciu s akademickými systémami.

\subsection{Výskumná medzera}

Analýza existujúcich riešení odhalila tri hlavné nedostatky: (1) absencia kontextuálnej AI asistencii pri plánovaní, (2) fragmentácia nástrojov vyžadujúca prepínanie medzi viacerými platformami, (3) nedostatočná podpora akademického prostredia (LMS integrácie, sledovanie študijných deadlinov). TIMA adresuje tieto medzery integrovaným prístupom.

\section{Problémová oblasť}

Hlavným problémom je \textbf{fragmentácia nástrojov} -- študenti musia prepínať medzi viacerými aplikáciami (kalendár, úlohy, poznámky), čo znižuje efektivitu. Druhý významný problém je \textbf{nedostatok kontextuálnej inteligencie} -- existujúce nástroje nereagují na aktuálnu záťaž používateľa ani neposkytujú adaptívne odporúčania.

Zároveň chybí \textbf{integrácia s akademickým prostredím} -- prepojenie s rozvrhovými systémami škôl, sledovanie deadlinov semestrálnych prác či koordinácia skupinových projektov.

Z ekonomického hľadiska študenti strácajú priemerne 3--5 hodín týždenne neefektívnym plánovaním a koordináciou, čo pri populácii vysokoškolákov v SR predstavuje značné ekonomické straty v podobe zníženej produktivity a predĺženého štúdia.

\section{Ciele projektu}

Projekt TIMA si kladie za cieľ vyvinúť a overiť funkčný prototyp inteligentného plánovača s nasledujúcimi špecifickými cieľmi:

\begin{enumerate}
\item \textbf{Technický vývoj}: Implementovať škálovateľný backend (Django + DRF) s relačným dátovým modelom do 12 mesiacov od začiatku projektu.

\item \textbf{AI integrácia}: Vyvinúť a integrovať AI modul (Google Gemini) pre automatickú prioritizáciu úloh, odhad času a inteligentné plánovanie do 18 mesiacov.

\item \textbf{Používateľské rozhranie}: Dodať responzívny frontend (Next.js 14) s dashboardom, vizualizáciami a Pomodoro timerom do 24 mesiacov.

\item \textbf{Integrácie}: Zabezpečiť obojsmernú synchronizáciu s Google Calendar a Tasks s konfliktovým riešením do 24 mesiacov.

\item \textbf{Validácia}: Realizovať pilotné nasadenie s minimálne 200 používateľmi na FIIT STU a vyhodnotiť dopad na produktivitu do 36 mesiacov.
\end{enumerate}

Ciele sú merateľné prostredníctvom technických míľnikov (funkčné moduly), používateľských metrík (čas do dokončenia úlohy, adherencia na plán) a kvalitatívneho hodnotenia (SUS dotazník, focus groups).

\section{Návrh riešenia}

\subsection{Architektúra systému}

TimeManager využíva modernú trojvrstvovú architektúru:

\textbf{Frontend} je implementovaný v Next.js 14 s využitím App Router, React Server Components a TypeScript pre type-safety. Tailwind CSS zabezpečuje responzívny dizajn a shadcn/ui poskytuje konzistentné UI komponenty s prístupnosťou (accessibility).

\textbf{Backend} je postavený na Django 5.0 s Django REST Framework pre RESTful API. PostgreSQL 16 slúži ako primárna databáza s podporou JSONB pre flexibilné ukladanie metadát a full-text search pre vyhľadávanie úloh.

\textbf{Integrácie} zahŕňajú Google Calendar API pre správu udalostí, Google Tasks API pre synchronizáciu úloh a Google Gemini API pre AI-powered odporúčania a automatickú kategorizáciu úloh.

\subsection{Kľúčové funkcionality}

\begin{enumerate}
\item \textbf{Inteligentná prioritizácia}: Gemini analyzuje deadline, náročnosť a kontext úlohy a navrhuje optimálny čas na jej splnenie.
\item \textbf{Automatická synchronizácia}: Obojsmerná synchronizácia s Google Calendar a Tasks zabezpečuje konzistenciu dát.
\item \textbf{Vizuálny prehľad}: Dashboard zobrazuje denný/týždenný plán s farebným kódovaním podľa Eisenhowerovej matice.
\item \textbf{Pomodoro timer}: Vstavaný časovač s notifikáciami a sledovaním produktivity.
\item \textbf{Kolaborácia}: Zdieľanie projektov a úloh v rámci študentských tímov.
\end{enumerate}

\section{Metodológia výskumu}

Projekt využíva iteratívny prístup s agile metódikou (SCRUM). Vývoj je organizovaný do 2--3 týždňových sprintov s pravidelnými review a retrospektívami.

\subsection{Vývojový proces}

\textbf{Continuous Integration/Deployment (CI/CD)}: Automatizované buildovanie, testovanie a deployment zabezpečuje rýchlu iteráciu a kvalitu kódu. Každý commit spúšťa pipeline zahŕňajúci unit testy, integračné testy a bezpečnostné skenery.

\textbf{Testovacia stratégia}: Kombinuje jednotkové testy (coverage $>$ 80\%), integračné testy API endpointov, end-to-end testy používateľských tokov a performance testy (load testing s expected 500 concurrent users).

\textbf{Bezpečnostný dizajn}: Implementuje OAuth 2.0 pre autentifikáciu, JWT tokeny pre API, šifrovanie osobných dát (AES-256), HTTPS everywhere a pravidelné bezpečnostné audity. GDPR compliance je zabezpečená Data Protection Impact Assessment (DPIA).

\subsection{Evaluačná metodológia}

Pilot bude prebiehať v dvoch fázach:

\textbf{Alfa testovanie} (mesiac 18--21): Uzavretá skupina 30--50 early adopters z FIIT STU, kvalitatívny feedback cez týždenné dotazníky a focus groups.

\textbf{Beta testovanie} (mesiac 24--36): Otvorený pilot pre minimálne 200 študentov, kvantitatívne meranie metrík:
\begin{itemize}
\item Čas strávený plánovaním (vs. baseline)
\item Adherencia na plán (počet dokončených úloh / plánovaných)
\item Task completion rate
\item Subjektívna spokojnosť (System Usability Scale -- SUS)
\item Net Promoter Score (NPS)
\end{itemize}

Validácia bude porovnávať experimentálnu skupinu (používatelia TIMA) s kontrolnou skupinou (tradičné nástroje) použitím paired t-testu pre štatistickú signifikanciu.

\subsection{Indexy a optimalizácie}

Pre efektívne vyhľadávanie sú vytvorené nasledujúce indexy:

\[
\begin{aligned}
&\text{idx\_tasks\_user\_deadline} \text{ ON Tasks(user\_id, deadline)} \\
&\text{idx\_tasks\_status} \text{ ON Tasks(status)} \\
&\text{idx\_tasks\_fulltext} \text{ ON Tasks USING GIN(to\_tsvector(title))}
\end{aligned}
\]

Časová zložitosť vyhľadávania úloh:
\[
O(\log n) \text{ pre indexované queries, kde } n = \text{počet úloh}
\]

\section{Technologické výhody}

\subsection{Next.js frontend}
Next.js 14 poskytuje server-side rendering (SSR) pre lepšie SEO a rýchlejšie načítanie, React Server Components znižujú bundle size o $\sim$30\% a App Router zjednodušuje routing a data fetching.

\subsection{Django backend}
Django ORM eliminuje SQL injection riziká, vstavaný admin interface urýchľuje vývoj a Django REST Framework poskytuje robustné API s automatickou dokumentáciou (OpenAPI/Swagger).

\subsection{PostgreSQL}
JSONB typ umožňuje flexibilné ukladanie AI odporúčaní bez potreby schema migrations, full-text search podporuje vyhľadávanie v slovenčine a ACID garantuje konzistenciu dát pri synchronizácii.

\section{Implementačné výzvy}

Hlavné technické výzvy zahŕňajú:

\begin{enumerate}
\item \textbf{Synchronizácia}: Riešenie konfliktov pri simultánnych zmenách v TIMA a Google službách pomocou Last-Write-Wins (LWW) stratégie s timestampmi.
\item \textbf{Rate limiting}: Google API majú limity (1000 požiadaviek/100s pre Calendar), je nutné implementovať request batching a caching.
\item \textbf{AI náklady}: Gemini API nie je zadarmo, optimalizácia promptov a caching odpovedí znižujú náklady.
\item \textbf{Privacy}: GDPR compliance vyžaduje šifrovanie osobných dát a explicitný súhlas používateľov.
\end{enumerate}

\section{Riziká a mitigačné stratégie}

\subsection{Technické riziká}

\textbf{Rate limiting Google API}: Google API majú obmedzenia (1000 požiadaviek/100s pre Calendar). Mitigácia: request batching, inteligentný caching, exponenciálne backoff, backup na lokálne úložisko.

\textbf{AI náklady}: Gemini API nie je zadarmo, náklady môžu eskalovať pri vysokom počte používateľov. Mitigácia: prompt optimalizácia, response caching (TTL 24h), rate limiting pre AI featury, plán B s open-source LLM (Llama 2).

\textbf{Škálovateľnosť}: Potreba zvládnuť 500+ simultánnych používateľov. Mitigácia: load testing od M12, horizontálne škálovanie (Kubernetes), database indexing, CDN pre statický content.

\subsection{Projektové riziká}

\textbf{Nízka adopcia pilotu}: Riziko nedostatočného počtu účastníkov. Mitigácia: gamifikácia (achievementy), incentívy (kredity, certifikáty), aktívny marketing na fakulte.

\textbf{GDPR compliance}: Porušenie môže mať právne dôsledky. Mitigácia: DPIA v M6, pravidelné audity, právne konzultácie, minimalizácia osobných dát.

\textbf{Časový sklz}: Oneskorenie míľnikov. Mitigácia: buffer čas v pláne (20\% reserve), agile prístup umožňujúci re-prioritizáciu, mesačné review.

\subsection{Komponent pre správu úloh}

Implementácia React komponenty pre zobrazenie úlohy s využitím shadcn/ui \cite{shadcn-ui}:

\begin{lstlisting}[language=JavaScript, caption=TaskCard komponent s Eisenhower prioritou]
"use client"

import { Card, CardContent, CardHeader } 
  from "@/components/ui/card"
import { Badge } from "@/components/ui/badge"
import { Button } from "@/components/ui/button"

interface Task {
  id: string
  title: string
  priority: 1 | 2 | 3 | 4
  urgency: 1 | 2 | 3 | 4
  deadline: Date
  status: "pending" | "active" | "completed"
}

export function TaskCard({ task }: { task: Task }) {
  const getQuadrant = () => {
    if (task.priority >= 3 && task.urgency >= 3)
      return { color: "red", label: "Urgentne" }
    if (task.priority >= 3 && task.urgency < 3)
      return { color: "yellow", label: "Dolezite" }
    if (task.priority < 3 && task.urgency >= 3)
      return { color: "blue", label: "Delegovat" }
    return { color: "gray", label: "Neskor" }
  }

  const quadrant = getQuadrant()

  return (
    <Card className="hover:shadow-lg transition">
      <CardHeader className="flex flex-row 
        items-center justify-between">
        <h3 className="font-semibold">
          {task.title}
        </h3>
        <Badge variant={quadrant.color}>
          {quadrant.label}
        </Badge>

\begin{lstlisting}[language=Python, caption=Google Calendar synchronizacia]
from google.oauth2.credentials import Credentials
from googleapiclient.discovery import build

class GoogleCalendarSync:
    def __init__(self, user):
        self.user = user
        self.credentials = self.get_credentials()
        self.service = build(
            'calendar', 'v3',
            credentials=self.credentials
        )
    
    def sync_task_to_event(self, task):
        event = {
            'summary': task.title,
            'description': task.description,
            'start': {
                'dateTime': task.deadline.isoformat(),
                'timeZone': 'Europe/Bratislava',
            },
            'end': {
                'dateTime': (
                    task.deadline + 
                    timedelta(
                        minutes=task.estimated_duration
                    )
                ).isoformat(),
                'timeZone': 'Europe/Bratislava',
            },
            'reminders': {
                'useDefault': False,
                'overrides': [
                    {'method': 'popup', 'minutes': 30},
                ],
            },
        }
        
        if task.google_calendar_event_id:
            # Update existing event
            event = self.service.events().update(
                calendarId='primary',
                eventId=task.google_calendar_event_id,
                body=event
            ).execute()
        else:
            # Create new event
            event = self.service.events().insert(
                calendarId='primary',
                body=event
            ).execute()
            task.google_calendar_event_id = event['id']
            task.save()
        
        return event
